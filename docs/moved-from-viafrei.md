# Moved from viafrei

The site shell and the files it is judged by came here from
[viafrei](https://github.com/mavrovde/viafrei) at **`ea91377ba`** (`release/2.6.18`), under
[viafrei-web#2](https://github.com/mavrovde/viafrei-web/issues/2). Commit `a958d0c` is that copy,
byte for byte and nothing else. Every change made to it afterwards is in a later commit, and none
of them changes what a visitor gets: every route of `scripts/site-pages.txt` renders the same here
as in a build of `ea91377ba` (see "The proof" below).

## The proof

- **The route diff.** This repository's image and a build of viafrei `ea91377ba` (a `git archive`,
  built in the same Node image) ran side by side on one stack, against the same pinned digest and
  the same placeholder § 5 identity. Every route of `scripts/site-pages.txt` was fetched from both.
  The status, `Location`, `Content-Type` and body were compared, with nonces, hashed asset names and
  clock times normalised.
  - The result: **431 of 431 routes identical** (340 × 200, 88 × 301, 3 × 404 on both sides).
  - The three 404s are the pre-1.6 redirects nginx answers.
- **The image.**
  - 267 MB, of which 141 MB is the Node binary. The shell's `dist` is 6.8 MB, and no `node_modules` ship.
  - `scripts/image-smoke.sh` passes: uid 10001, read-only root, no npm, the static files byte-identical,
    the GeoIP builder, `/healthz`, `/de` with no digest, the CSP and a 404.
  - `scripts/stack-smoke.sh` passes: the shell renders `/de`, `/en` and `/de/autobahn` from the pinned
    releases and uses every fragment it asks for.
- **The browser suite**, in the arm64 Playwright image (`mcr.microsoft.com/playwright:v1.63.0-noble`
  with the DejaVu fonts), the whole of `packages/web/e2e`: 103 files, 4464 cases.
  - The full run: 4435 passed and 29 failed. 23 of the failures were `place-fuel-1065`, which
    still read viafrei's digest source. It now reads the pinned l10n, and its re-run passes.
  - After that fix, a re-run of the six failing files leaves 4 failures. All of them are the
    "eight desktop screens" bound of #1180 (8.03 to 8.12 screens against 8): `desktop-1180`,
    `desktop-place-1180` and `desktop-station-1180` (2).
  - The same files from viafrei `ea91377ba`, run in the same container, fail the same
    cases with the same figures, plus two more. So the bound fails at the source too, on this
    architecture. CI runs the amd64 image.
  - Two cases that timed out once under load (the link walk of `site.e2e.ts`, one width of
    `station-board-1083`) passed on the re-run.
- **The visual baselines** were re-recorded once, in the amd64 Playwright image that CI's runner
  matches: 208 screenshots, 80 of them byte-changed from viafrei's. A compare against the new set
  passes (208 within 0.2 %). That shows the run is deterministic; it says nothing about the old set.
  - Why 80 changed: viafrei's pages moved on after its last recording (the #1205 paragraph of the
    Datenschutz page, the catalogue versions on the developers page, new News entries), and some
    fragment renders differ below the compare threshold, which a re-recording writes anyway.
- **The four `*1180*` browser files** (`desktop-1180`, `desktop-home-1180`, `desktop-place-1180`,
  `desktop-station-1180`) could not be measured in the amd64 image on this laptop. Under emulation 70
  of the web side's 73 cases failed on the files' own 2-second navigation timeout before any figure
  was read, and the reference side was stopped unfinished. The amd64 figures come from CI's `Web`
  job, on native amd64; the arm64 figures above stand.

## What could not move without a change outside the UI

- **viafrei-app ships no type declarations.** The tests' types are inferred from its JavaScript
  (`scripts/pinned-app.sh`). `scripts/pinned-types.mjs` re-declares 3 inferred names and stubs 80
  type-only names as `any`. The fix is in viafrei: ship the `.d.ts` (viafrei#1318).
- **The infra side of the tests.** This repository carries no copy of viafrei-infra's files. The
  34 cases that read them (the edge, the production compose file, the deploy and the host jobs) are
  skipped here with a `cross-repo(viafrei-infra)` marker and listed above; viafrei-infra holds those
  agreements (viafrei-infra#32): the case names here, the assertions there. It also mounts `/srv/site-static/*` and runs `geoip-build.mjs` from this image
  (viafrei-infra#31).
- **The catalogue and the News feed** (`src/generated/*.json`) are generated in viafrei, from its
  CHANGELOG and the MCP server, and arrive here as copies. Until viafrei publishes them as a release
  asset, refreshing them is a hand-off.
- **The `speed` kind** needs viafrei-app ≥ 2.6.18 released. Then `images.pin` is bumped and the
  three pin-skew cases are un-skipped.
- **Byte-identical source copies** (`src/site/slug.ts`, `src/lib/log-mask.ts`): no side checks them
  against the ingest originals any more. viafrei should keep that check until the copies retire.
- **The status console's privacy assertions** stay in viafrei with the console.
